# RemNote public listing checklist

## Objective

Publish Signal Repeat so that RemNote users can discover and install it from
**Settings → Plugins → Browse**.

This checklist is separate from publishing a GitHub Release. A GitHub Release
provides the immutable build artifact; the RemNote listing makes the plugin
discoverable inside RemNote.

## Current candidate

- Product: Signal Repeat for RemNote
- Publisher: Signal, Not Volume
- Repository: <https://github.com/signal-node/signal-repeat-remnote>
- Candidate version: `0.1.2`
- Candidate release: pending validation, merge, and tag
- Candidate asset: `signal-repeat-remnote-v0.1.2.zip`
- Candidate commit and SHA-256: record after the verified build reaches `main`
- Stable baseline release:
  <https://github.com/signal-node/signal-repeat-remnote/releases/tag/v0.1.0>
- Stable baseline SHA-256:
  `5bc39ff2b851163103a2c4731ee213d867958498dc581c64f4f8c46e80a6cfb0`
- Supported in v0.1.0: RemNote Web and Desktop
- Not supported in v0.1.0: RemNote Mobile

## Step 1 — Verify the immutable release candidate

- [ ] Annotated `v0.1.2` tag points to the verified `main` commit.
- [ ] GitHub Release is public and marked Latest.
- [ ] Published ZIP downloads successfully.
- [ ] Downloaded ZIP is byte-for-byte identical to the local verified build.
- [ ] SDK manifest and logo validation pass.
- [ ] TypeScript passes.
- [ ] All automated tests pass.
- [ ] Production build passes.
- [ ] Selected-text, flashcard-answer, and popup entry points render from the
  downloaded archive.

## Step 2 — Install the published ZIP in RemNote

1. Open **Settings → Plugins → Build**.
2. Disable the localhost development copy of Signal Repeat.
3. Select **Upload plugin**.
4. Upload the ZIP downloaded from the GitHub Release, not an unverified local
   rebuild.
5. Confirm that RemNote displays Signal Repeat version `0.1.2`.
6. Repeat the acceptance smoke test using synthetic content.
7. Confirm that no Rem content, card rating, queue state, or scheduling data is
   changed.
8. Confirm that no learning content is logged, stored, or transmitted.

Do not keep the localhost build and release build active simultaneously during
acceptance testing.

## Step 3 — Prepare listing material

Required product information:

- Name: `Signal Repeat`
- Short description:
  `Repeat only what matters with short, focused sessions in RemNote.`
- Publisher: `Signal, Not Volume`
- Repository and support URL:
  <https://github.com/signal-node/signal-repeat-remnote>
- Privacy statement: use the **Privacy and permissions** section of `README.md`.
- Installation and usage: use the matching sections of `README.md`.
- Supported platforms: explicitly state **RemNote Web and Desktop**.
- Known limitations: mobile is disabled; cloze-answer extraction and List,
  Partial, and recursive multi-line answer extraction are not included.

Visual material:

- The RemNote SDK currently supplies an autogenerated `S` logo because no
  `public/logo.svg` or `public/logo.png` is packaged.
- A dedicated Signal Repeat logo is recommended before final store approval,
  but the current SDK validator accepts the autogenerated logo.
- `docs/assets/signal-repeat-session.jpg` is the existing product screenshot.
- All listing screenshots must use synthetic content and must not expose real
  learning material or personal data.

### `public/logo.svg` requirements

Confirmed by the RemNote Plugin SDK `0.0.46` validator:

- the exact path and lowercase filename are `public/logo.svg`;
- `public/logo.png` is also recognized, but `logo.svg` takes precedence when
  both files exist;
- a logo is currently optional because the SDK falls back to an autogenerated
  logo;
- the validator currently checks file presence only; it does not enforce SVG
  dimensions, a file-size limit, or a particular `viewBox`;
- the project build copies the file to `/logo.svg` at the root of `dist` and the
  release ZIP.

Project requirements for a robust store icon:

- use a square SVG canvas with `viewBox="0 0 80 80"`;
- keep the mark recognizable at 24–48 px and leave padding around the edges;
- use simple vector paths and a limited color palette that remains legible on
  light and dark RemNote themes;
- include a transparent or deliberately filled background rather than relying
  on the page background;
- do not include scripts, event handlers, animation, external URLs, remote
  images, embedded HTML, tracking, or external fonts;
- convert any lettering to paths or use a symbol that does not depend on an
  installed font;
- include a concise `<title>Signal Repeat</title>`;
- keep the file small; under 50 KB is a project recommendation, not an SDK
  requirement;
- render the SVG at 24, 48, and 80 px on light and dark backgrounds before
  approval.

Acceptance checks:

```sh
mise run build
archive_name="$(mise exec -- npm run --silent archive-name)"
unzip -l "$archive_name" | grep 'logo.svg'
```

Also load the built ZIP in RemNote and confirm that the icon is visible in the
Build/Manage list. The RemNote team must confirm any additional store-specific
dimension or branding requirements because the current public documentation
does not specify them.

The dedicated logo is introduced in v0.1.1. Do not replace or move the existing
v0.1.0 tag or artifact.

## Step 4 — Confirm RemNote's current submission channel

The public plugin documentation explains development and local installation,
but does not currently document a self-service public-listing submission form.
The in-app **Build** tab exposes **Upload plugin** and **Develop from localhost**,
but no public submission control was visible during this review.

Contact RemNote support or the official plugin developer channel and ask for
the current review/submission path before sending the binary anywhere else.

Suggested message:

> Hello RemNote team, I would like to submit Signal Repeat for listing in
> Settings → Plugins → Browse. It is a focused repetition plugin for RemNote Web
> and Desktop. The public source repository is
> https://github.com/signal-node/signal-repeat-remnote and the verified v0.1.2
> release is
> https://github.com/signal-node/signal-repeat-remnote/releases/tag/v0.1.2.
> The plugin does not transmit or persist learning content and does not modify
> Rem content, flashcard ratings, queue state, or scheduling data. Could you
> please provide the current submission requirements and review process for a
> community plugin listing?

Record the response and update this checklist if RemNote requires a particular
logo size, screenshot dimensions, form, repository permission, or delivery
method.

## Step 5 — Submit for review

Before submission, confirm:

- [ ] The exact submitted ZIP has the published v0.1.2 SHA-256 recorded after
  release verification.
- [ ] The listing states Web/Desktop support accurately.
- [ ] Mobile support is not claimed.
- [ ] Permissions match the manifest and are explained.
- [ ] Privacy and support links are present.
- [ ] Screenshots contain synthetic content only.
- [ ] Any required dedicated logo has been added through a new release.

Submit only through the channel confirmed by RemNote. Save the submission ID or
support conversation link without copying private account details into the
repository.

## Step 6 — Respond to review feedback

- Convert requested code changes into a GitHub Issue and focused Pull Request.
- Re-run typecheck, tests, build, ZIP integrity, and RemNote acceptance tests.
- Publish code or binary changes as a new patch version.
- Do not overwrite an existing tag or release asset.

## Step 7 — Verify the public listing

After approval:

1. Find Signal Repeat in **Settings → Plugins → Browse** using a normal user
   account/session.
2. Verify the displayed name, publisher, description, icon, screenshots,
   permissions, repository, and supported platforms.
3. Install from Browse rather than Build.
4. Run the synthetic-content acceptance smoke test again.
5. Verify that **Report bugs** points to the correct GitHub repository.
6. Record the published listing URL and approval date in the release notes or a
   follow-up documentation Pull Request.
